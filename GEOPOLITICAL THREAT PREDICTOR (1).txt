1. Introduction
Geopolitical Threat Predictor is a Python terminal application that converts three user-supplied indicators into a modeled threat index and supplements that score with similarity analysis against historical crises. The repository describes it as an educational computational model rather than a statistically validated forecasting system.
The three indicators are inflation level, border tension level, and resource scarcity level. Each is entered from 1 to 10. The program computes a weighted current-risk score, compares the current vector with historical cases using weighted Euclidean distance, selects the five most similar cases, calculates a similarity-weighted historical-risk score, and combines the two components.
The repository explicitly states that the model does not use machine learning, regression, Bayesian probability, statistical forecasting, or large-scale datasets. Its primary focus is therefore mathematical modeling and Python programming.
1.1 Objectives
•	Represent selected geopolitical conditions numerically.
•	Apply weighted mathematical scoring to current conditions.
•	Compare current conditions with historical crisis patterns using distance-based similarity.
•	Use the most similar historical cases as contextual input.
•	Produce a repeatable terminal report with intermediate scores and classification.
•	Demonstrate input validation, loops, dictionaries/lists, functions, sorting, and mathematical computation.
 2. Problem Statement
Geopolitical situations involve many interacting economic, political, diplomatic, social, and strategic factors. For an educational computational model, representing such a situation as a single numerical value is challenging because different indicators do not necessarily have equal influence.
The project addresses this by defining three simplified indicators with explicit weights, then adding historical context by measuring how close the current indicator vector is to predefined historical cases. The resulting index demonstrates how multiple numerical signals can be combined into a structured computational assessment.
The project is intentionally scoped down. Historical indicator values, weights, thresholds, and outcome scores are model assumptions and are not official historical measurements or probabilities.

8. Design Decisions & Rationale
Decision	Rationale
Three indicators	Keeps the model understandable for an introductory mathematical-programming project.
20/30/50 weights	Makes the relative contribution of each factor explicit.
Weighted Euclidean distance	Provides a simple measure of closeness between multi-dimensional vectors.
Top five cases	Focuses historical influence on the most similar examples.
Outcome score mapping	Allows qualitative outcomes to participate in a numerical weighted average.
60/40 combination	Makes current conditions dominant while retaining historical context.
Named constants	Makes assumptions easy to inspect and modify.
Terminal interface	Avoids GUI dependencies and keeps focus on Python logic.

 9. Implementation Details
9.1 Model Parameters
Constant	Value
WEIGHT_INFLATION	0.20
WEIGHT_TENSION	0.30
WEIGHT_SCARCITY	0.50
CURRENT_RISK_WEIGHT	0.60
HISTORICAL_RISK_WEIGHT	0.40
TOP_HISTORICAL_CASES	5
HIGH_RISK_THRESHOLD	75.00
MODERATE_RISK_THRESHOLD	45.00
MIN/MAX INPUT	1.00 / 10.00
9.2 Current Risk
Current Risk = (Inflation×0.20 + Border Tension×0.30 + Resource Scarcity×0.50)×10
9.3 Similarity
Distance = √[0.20(Ic−Ih)² + 0.30(Tc−Th)² + 0.50(Sc−Sh)²]
The source normalizes distance against the maximum possible distance for the 1–10 range and converts it into a 0–100 similarity percentage.
9.4 Historical Risk
Historical Risk = Σ(Outcome Score×Similarity) / Σ(Similarity), using the five selected cases.
9.5 Final Threat Index
Final Threat Index = (Current Risk×0.60) + (Historical Risk×0.40)
9.6 Classification
<45 → LOW MODELED THREAT
45–74.99 → MODERATE MODELED THREAT
≥75 → HIGH MODELED THREAT

11. Testing Approach

11.1 Testing Limitation
No unittest/pytest suite is present in the public repository, so this report does not claim a numerical automated-test pass rate. Adding unit tests for get_valid_rating(), calculate_current_risk(), calculate_similarity(), historical aggregation, and classification would strengthen the project.
 12. Challenges Faced
•	Reducing a complex geopolitical problem to a small number of numerical indicators.
•	Choosing explicit weights while documenting that they are model assumptions.
•	Comparing current conditions with historical cases whose indicator values are themselves normalized model inputs.
•	Converting distance into an interpretable similarity percentage.
•	Combining qualitative historical outcomes with quantitative similarity scores.
•	Designing validation for invalid numbers, non-finite values, range violations, and exit commands.
•	Keeping the program reusable through a loop while retaining a clean exit.
12.1 Key Methodological Limitation
The largest limitation is model validity rather than syntax: historical indicator values, outcome scores, weights, and thresholds are assumptions embedded in the project. The output should therefore be interpreted as a deterministic modeled index produced by the defined rules.
 13. Learnings & Key Takeaways
•	Converted qualitative concepts into numerical variables for computational modeling.
•	Applied weighted sums to combine indicators.
•	Applied Euclidean distance to compare multi-dimensional vectors.
•	Used normalization to convert distance into bounded similarity.
•	Used sorting and slicing to identify the most similar cases.
•	Used dictionaries/lists to represent structured historical data.
•	Separated validation and mathematical operations into functions.
•	Used named constants to expose model assumptions.
•	Distinguished deterministic scoring from statistically validated prediction.
•	Recognized the need for testing and empirical validation before real-world interpretation.
13.1 Academic Relevance
The project demonstrates Python fundamentals, functions, loops, conditionals, dictionaries, lists, sorting, exception handling, the math module, numerical formulas, normalization, and algorithmic decomposition.
